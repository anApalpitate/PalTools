# 图鉴与配种界面 Bug

## 1. 范围与优先级

- 页面：图鉴 → 任意帕鲁详情弹窗
- 影响环境：Windows Electron 与浏览器版
- 建议优先级：P1
- 当前状态：待修复

本文件记录两个相关的详情弹窗布局问题。修复应保持背景页面锁定，并确保左右两栏独立滚动，不能重新引入整页或整个弹窗随滚轮移动的问题。

## 2. Bug 1：左侧详情不能独立上下滚动

### 当前现象

- 桌面布局中只有右侧“主动技能”面板可以上下滚动。
- 左侧基础资料、数值、工作适性、固有被动技能和掉落物内容较长时，无法在左栏内部继续向下浏览。
- 当前详情弹窗使用 `overflow: hidden`，右栏 `.active-skills-panel` 有独立滚动，但左栏 `.detail-main` 没有对应的滚动容器。

### 预期行为

- 左侧详情和右侧主动技能均可独立上下滚动。
- 左栏滚动条显示在左侧边缘；右栏滚动条继续显示在右侧边缘。
- 非悬停、非键盘聚焦且没有发生滚动时隐藏滑块，避免两条滚动条长期占据视觉注意力。
- 鼠标进入、键盘聚焦或正在滚动时显示滑块；停止操作后平滑隐藏。
- 滚动左栏不会带动右栏、整个弹窗或背景页面，右栏亦然。

### 建议实现

1. 为左侧内容增加专用滚动容器，不直接让整个 `.detail-dialog` 滚动。
2. 左右滚动容器统一设置：
   - `min-height: 0`
   - `overflow-y: auto`
   - `overscroll-behavior: contain`
   - 一致的最大高度和主题滚动条宽度
3. 建议增加左栏外层包装元素来承载“滚动条在左侧”的布局，内容层继续保持正常的从左到右排版。避免仅对现有 Grid 粗暴设置 `direction: rtl`，以免影响文字、网格顺序和可访问性。
4. 滑块默认透明，在容器 `:hover`、`:focus-within` 或临时 `.is-scrolling` 状态下显示。若需要“停止滚动后隐藏”，使用短暂状态类实现，不依赖永久显示的系统滚动条。
5. 滚动条隐藏时仍保留稳定的 gutter 或等价内边距，避免内容在滑块出现和消失时左右跳动。
6. 低高度和窄屏回退仍允许弹窗内部整体滚动；不得形成无法触达内容的双重嵌套滚动死区。

### 验收标准

- [ ] 1920×1080 桌面布局下，左栏和右栏均可独立滚动。
- [ ] 左栏滑块位于详情内容左侧，右栏滑块位于主动技能右侧。
- [ ] 静止状态下滑块不可见；悬停、键盘聚焦或滚动时清晰可见，内容不会横向跳动。
- [ ] 滚动任一栏时，另一栏的 `scrollTop` 不变，背景页 `scrollY` 不变。
- [ ] 滚动到左右栏首尾时不会把滚动事件穿透到背景页面。
- [ ] 1536×864、1366×768、低高度窗口和窄屏回退下均能访问全部详情内容。
- [ ] Chromium/Electron 和 Firefox 的滑块行为一致或具备可接受的降级表现。

## 3. Bug 2：固有被动技能区域视觉错位

### 当前现象

- “固有被动技能”标题、空状态或技能卡片与相邻“工作适性”“掉落物品”区域的起始边缘和垂直节奏不一致。
- 当前桌面样式通过 `.detail-work + .detail-section` 结构选择器把第一个详情区放入第二列。内容高度变化时，固有被动技能容易悬在工作适性右侧，形成错位和不自然的留白。
- 被动技能 Rank 使用浮动布局，名称较长或窗口较窄时存在与标题、描述挤压的风险。

### 预期行为

- 固有被动技能作为完整、稳定的详情区块，与其他左栏模块保持统一的标题位置、间距、边框和内容宽度。
- 有技能和无技能两种状态都不应出现标题悬空、卡片错列或大面积不规则留白。
- 技能名称、Rank 和描述具有明确层级；长名称和多行描述不会重叠。

### 建议实现

1. 移除依赖兄弟顺序的 `.detail-work + .detail-section` 布局规则，为工作适性、固有被动技能和掉落物品使用明确的 class 或 Grid area。
2. 建议将固有被动技能放在工作适性下方并占满左栏宽度；若保留双列卡片，仅卡片列表内部使用两列。
3. 被动技能卡片头部改为 Flex/Grid：
   - 名称占用可伸缩空间；
   - Rank 右对齐且不压缩名称；
   - 描述独占下一行。
4. 空状态文本放在标题正下方，使用与其他空数据区域一致的内边距和弱提示颜色。
5. 窄屏时被动技能卡片列表退化为单列，不使用浮动定位。

### 验收标准

- [ ] 固有被动技能标题与工作适性、掉落物品标题左边缘一致。
- [ ] 区块按“工作适性 → 固有被动技能 → 掉落物品”稳定排列，不随内容数量改变位置。
- [ ] 空状态、有一项、两项及多项被动技能时均无错位或异常留白。
- [ ] 长技能名称、Rank 和多行描述不重叠、不溢出、不遮挡。
- [ ] 1920×1080、1536×864、1366×768 和窄屏布局均保持视觉一致。

## 4. Bug 3：默认顺序不能调整排列方向

### 当前现象

- “排序数值”选择“默认顺序”时，“排列方式”下拉框被禁用。
- 当前领域逻辑在 `sortKey` 为空时直接返回过滤结果，无法按相反方向查看图鉴编号。

### 预期行为

- 默认顺序视为“图鉴编号顺序”，同样支持升序和降序。
- 建议将选项文案改为“图鉴编号（默认）”或通过辅助说明明确默认顺序的含义。
- 图鉴编号升序时从较小编号排到较大编号；降序时从较大编号排到较小编号。
- 没有图鉴编号的条目无论升序还是降序都稳定放在有编号条目之后。

### 建议实现

1. “排列方式”在默认排序下也保持可用。
2. 将默认排序纳入统一比较器，不再以 `sortKey` 为空为由直接返回原数组。
3. 复用图鉴编号的 numeric 比较，并以内部 ID 作为同编号或无编号条目的稳定兜底。
4. 重置后恢复“图鉴编号升序”，避免默认状态出现倒序或依赖来源文件顺序。
5. 数值字段仍保持现有规则：空值始终置后，相同数值按图鉴编号和内部 ID 稳定排列。

### 验收标准

- [ ] 选择“图鉴编号（默认）”时排列方式控件可用。
- [ ] 升序结果从 `#001` 开始，降序结果从最大有效图鉴编号开始。
- [ ] 无图鉴编号条目在两个方向下都位于有效编号之后。
- [ ] 搜索、属性和工作适性过滤变化后，结果继续使用当前排列方向。
- [ ] 点击重置后恢复图鉴编号升序。

## 5. Bug 4：重置按钮视觉不够醒目

### 当前现象

- 图鉴筛选区的“重置”使用弱化按钮样式，与深色背景和相邻下拉框对比不足。
- 当用户组合多个筛选条件后，不容易快速识别清除入口。

### 预期行为

- 重置按钮使用更鲜明、与页面主题一致的颜色，但不应呈现为危险删除操作。
- 默认、悬停、按下和键盘聚焦状态都清楚可辨。
- 鲜艳颜色不能压过页面主导航，也不能降低文字对比度。

### 建议实现

1. 为筛选重置增加独立 modifier class，不改变所有 `.quiet-button`。
2. 使用较高饱和度的主题绿色或金绿色背景，并提供明确边框。
3. `hover` 适度提高亮度，`active` 降低亮度或轻微下压，`focus-visible` 增加外圈。
4. 若后续增加“当前没有筛选条件”的禁用状态，禁用时再回到弱化样式。

### 验收标准

- [ ] 重置按钮在图鉴筛选区中无需悬停即可快速识别。
- [ ] 普通文字与按钮背景达到清晰对比。
- [ ] hover、active、focus-visible 状态完整，键盘操作可见。
- [ ] 1920×1080、1366×768 和窄屏下按钮不挤压排序控件。

## 7. Bug 5：配种结果卡片重复展示子代名称

### 当前现象

- 配种公式中已经展示子代头像、中文名和“子代”角色。
- 卡片底部 `.result-summary` 再次展示子代中文名、英文名和图鉴编号，信息重复并增加卡片高度。
- 正向配种和子代反查共用 `FormulaCard`，因此当前重复区域会同时出现在两类结果卡片中。

### 预期行为

- 删除卡片底部重复的子代摘要区域，缩短卡片高度。
- 配种公式本身继续清晰展示两只亲本、运算符和子代。
- 子代的英文名或图鉴编号若仍有保留价值，应放入子代节点的次级信息或悬停提示，不再单独占用整行。

### 建议实现

1. 从 `FormulaCard` 删除 `.result-summary`。
2. 同步删除仅服务于该摘要的样式，并调整 `.result-card` 的 gap、padding 和底部留白。
3. 保留 `breeding-equation` 的完整 `aria-label`，不能因视觉精简损失“亲本 A + 亲本 B → 子代”的可访问文本。
4. 默认建议同时作用于正向配种和子代反查；若产品只希望修改正向结果，需要先拆分组件或增加显式变体。

### 验收标准

- [ ] 配种结果卡片底部不再重复显示子代名称。
- [ ] 卡片高度明显减小，连续结果列表可在同一屏展示更多公式。
- [ ] 子代头像、中文名和角色仍清晰可见。
- [ ] 正向查询和反向查询的公式布局均无异常留白。
- [ ] 屏幕阅读器仍能读取完整配种关系。

## 8. Bug 6：目标子代选择框过长

### 当前现象

- “目标子代”组合框在路径规划中占据剩余的大部分横向空间；反向查询中的“选择目标子代”也使用等分宽度。
- 在宽屏下控件显得松散，与规划方式、搜索框等相邻控件比例不协调。

### 预期行为

- 目标子代选择框适度缩短，与相邻控件形成清晰、紧凑的比例。
- 下拉候选面板仍能展示完整中文名、英文名和图鉴编号。
- 不能通过固定过小宽度造成已选帕鲁文字不可读或窄屏溢出。

### 建议实现

1. 桌面布局为目标子代列设置合理的 `minmax` 或 `max-width`，建议视觉宽度约 360–460 px，再结合实际截图确定。
2. 路径规划中把剩余空间留给布局间距，而不是让目标框无限拉伸。
3. 反向查询中可采用“目标子代固定上限 + 搜索框弹性占满”的列布局。
4. 下拉候选面板宽度至少与输入框相同；必要时允许候选面板略宽于输入框。
5. 窄屏断点下恢复 `width: 100%` 并纵向排列。

### 验收标准

- [ ] 宽屏下目标子代选择框不再横向占满可用空间，整体比例协调。
- [ ] 规划方式、指定代数和反查搜索框不被挤压。
- [ ] 已选中文名、英文名和图鉴编号具备合理可读空间。
- [ ] 候选列表不会被输入框宽度裁切，滚动和键盘选择保持可用。
- [ ] 1366×768 和窄屏下无水平溢出，窄屏控件可恢复全宽。

## 10. 完成定义

只有在已明确的 Bug 均通过对应验收标准、自动化回归和多尺寸真实浏览器检查后，才可标记为完成。路径规划待补充项必须先明确需求再进入实施。修复阶段不得改回“整个详情弹窗滚动”或解除背景页面锁定。
