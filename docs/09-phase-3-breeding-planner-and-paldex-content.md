# 第三阶段：反向配种、路径规划与图鉴内容

## 1. Schema v3

第三阶段从公共类型、生成数据、领域逻辑和界面中移除了 `Gender` 与亲本性别字段。PalCalc 原始两条性别记录仍作为来源完整性检查保留，但输出规范为两个无性别公式。

配方只存一份紧凑三元组。`recipesByPair` 支持双亲查子代，`parentsByChild` 支持目标反查和路径搜索，两者均引用同一配方下标。这样避免把 44,851 个完整对象重复写入桌面包。

新增内容：

- 帕鲁上的主动技能引用、固有被动和掉落记录。
- 去重 `skills.json` 与 `items.json`。
- 本地掉落物 WebP 图标及哈希。
- manifest 中的内容数量和无性别规范化策略。

## 2. 代数数学定义

设起始集合为 \(S\)，每个 \(p \in S\) 的代数为：

```text
generation(p) = 0
```

若公式 `A + B → C` 被使用，则该树节点中的：

```text
generation(C) = max(generation(A), generation(B)) + 1
```

因此代数是配种树的最大深度，不是所有配种操作的总数。指定 N 代要求目标根节点恰好位于 N，不接受“最多 N 代”。第 0 代目标表示目标本身已在当前起点集合中。

## 3. 起点集合

### 已拥有

- 保存到 `localStorage` 键 `paltools.path-starts.v1`。
- 刷新和重新启动后保留。

### 临时起点

- 只保存在 React 会话状态。
- 刷新或关闭应用后消失。

两者都只记录帕鲁种类，不记录个体数量。同种帕鲁可用于同种亲本公式，也可在不同树分支重复出现。

## 4. 最少代数

算法对所有已知帕鲁维护当前最佳状态，从第 0 代起反复扫描配方。只有两个亲本都可达时才产生子代候选。候选比较顺序：

1. 代数更少。
2. 配种节点总数更少。
3. 不同中间帕鲁更少。
4. 亲本及子代内部 ID 组成的稳定字典序。

当一轮没有任何状态改善时结束。这个计算不受管理员展示上限影响，因此目标即使需要超过六代，也能报告准确的最少代数。

若最少代数不超过当前上限，才递归构造完整推荐树；超过上限时不创建 React Flow 节点或边，并提示增加起点或调整配置。

## 5. 指定 N 代与循环

指定模式先构建 `pal × depth` 的精确可达性表，再从目标和 N 反向选择公式。配方成立的条件是：

```text
max(parentADepth, parentBDepth) + 1 = nodeDepth
```

构树时保存当前根到叶路径上的帕鲁集合。如果候选会让同一帕鲁再次出现在这条路径中，则排除该候选。不同兄弟分支可以重复使用同一种帕鲁，因为系统不记录个体数量。

精确搜索具有安全预算，并使用稳定候选顺序。可区分以下无解状态：

- 起点集合为空。
- 目标不在配方矩阵。
- 目标从当前起点不可达。
- 指定 N 低于最少代数。
- N 代内有数值可达性，但不存在满足无环约束的树。

## 6. 节点替代配方

每个配种节点记录在相同起点、相同节点代数和当前祖先约束下仍可成立的替代配方。用户选择替代项后，使用该节点路径作为偏好重新运行 Worker，并重建该子树，其他节点继续遵循确定性排序。

默认只展示一棵推荐树，避免指数级枚举所有方案。

## 7. Worker 与过期请求

路径页把紧凑索引、起点、目标、模式、代数上限和节点偏好发送给 Vite Web Worker。每个请求有递增编号；新输入会终止旧 Worker或丢弃旧编号响应。这样管理员调低上限、快速更换目标或修改起点时，不会被旧结果覆盖，也不会阻塞主界面。

## 8. 管理员配置

配置结构：

```ts
interface AppConfig {
  schemaVersion: 1
  pathPlanner: {
    maxExactGeneration: number
  }
}
```

- 存储键：`paltools.admin-config.v1`。
- 默认：6。
- 可配置：1–12 的整数。
- 代码硬上限：12。
- 缺失使用默认；损坏、非整数和越界回退为 6，并显示恢复提示。
- “恢复默认值 6”立即写回有效配置。
- 降低上限会收缩当前指定 N、清除旧树并触发新计算。

## 9. 图鉴内容

主动技能仅从现有 299 个详情页的技能卡解析，不抓取技能详情页。技能目录保存通用字段，帕鲁引用保存解锁等级和必要的页面专属覆盖字段。

固有被动只表示 paldb 当前页面明确列出的固有被动，不推演可继承被动。掉落记录保存数量上下限、小数概率和可选等级条件；物品目录负责名称与本地图标。

没有直接 paldb 页面时三个字段均为 `null`；页面确认没有内容时为 `[]`。

## 10. UI 与验收

- 配种页有“双亲查子代 / 目标反查 / 路径规划”三个模式，不存在性别控件。
- 反向结果每页 50 条，搜索作用于全部结果。
- React Flow 自上而下展示图片、名称、编号、代数与起点/配种状态，禁止编辑连线。
- 文本步骤与画布表达同一路线。
- 图鉴详情桌面双栏，768px 纵向；主动技能字段不折叠。
- EXE 冒烟验证 Schema v3、反向索引、默认 6、主动技能卡和掉落图标。

当前阶段不处理个体数量、蛋糕、孵化时间、被动继承概率或存档导入。
