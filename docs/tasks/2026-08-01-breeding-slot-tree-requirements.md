## 2. 目标与非目标

### 2.1 目标

1. 使用确定性的结构槽位表达配种树，不再把节点坐标当作用户可自由编辑的数据。
2. 让空方案、独立树、树的可继续扩展位置和拖放目标始终可见、可理解。
3. 保持严格树结构；需要复用既有分支时复制节点实例和关系，不通过共享节点重新引入 DAG。
4. 合并选择与空白区域平移为新的“光标”模式，同时保留不会误选或误拖节点的“仅平移”模式。
5. 提供固定且不需要配置的剪贴、粘贴和缩放快捷键。
6. 将左右辅助面板收纳为类似 Codex 的边缘图标入口。
7. 将查询页的“追加到当前方案”改为与方案解耦的配方标记，并在配种图右侧栏集中展示。
8. 修复导出时序、直接加入显示、平移保存风暴和浏览器原生拖拽问题。

### 2.2 非目标

- 不恢复自由坐标拖动、React Flow、自动路径规划、最少代数或指定代数功能。
- 不改变静态配方数据、无性别配方语义或每个子代最多一条生成关系的约束。
- 不增加快捷键设置页、账号、云同步、运行时遥测或第三方请求。
- 不把图形视图作为唯一表达；等价文本关系列表继续保留。
- 不再允许输入亲代或输入目标子代页面直接创建、修改或保存当前配种方案。

## 3. 采用的需求解释

“无需使用画布格式”解释为：**取消自由坐标画布的数据与操作模型，但保留承载大型树所必需的可缩放、可平移视口**。缩放和平移只改变观察方式，不改变树结构、槽位顺序或节点关系。

“图是树结构”解释为严格的有序二叉配种森林：

- 一棵树表示一个连续配种分支，亲本在上、子代在下。
- 每条完整关系仍是不可拆分的 `亲本 A + 亲本 B → 子代`，并保存精确 `recipeIndex`。
- 一个节点实例只能位于一棵树的一个槽位中；不得被两条后续分支共享。
- 同一种帕鲁可以通过多个实例重复出现。
- 复用既有节点或分支时深复制所需的来源子树并生成新 ID，原分支不被静默改写。

“复制更顶层的树到同一层高度”解释为结构复制，不是伪造帕鲁、空白代数或仅修改一个自由坐标。两个待组合分支高度不同时，较高/较短的一侧复制为独立实例，并把其结果节点对齐到较低/较深一侧的结果层；随后在下一层生成共同子代。若另一侧也会因本次操作形成节点共享，则同样复制该侧，最终结果必须仍是严格树。

## 4. 槽位与树的概念

### 4.1 结构对象

| 对象 | 定义 |
| --- | --- |
| 帕鲁节点 | 一个具体节点实例，保存 `id`、`palId` 和来源；不保存可自由拖动的业务坐标 |
| 完整关系 | 两个不同亲本节点实例和一个子代节点实例组成的原子关系，保存 `recipeIndex` |
| 配种树 | 无共享节点的完整二叉结构；结果端在下，来源端在上 |
| 配种森林 | 当前方案中从左到右有稳定顺序的零棵或多棵配种树 |
| 空树槽位 | 创建一棵新独立树的入口，不是持久化帕鲁节点 |
| 叶端槽位 | 非空树可继续组合/扩展的位置；是交互占位，不伪装成已有帕鲁 |
| 占用槽位 | 已由帕鲁节点或完整子树占据的结构位置 |

槽位位置由树结构、树高、同层顺序和稳定间距确定。布局必须是同一输入得到同一结果，不持久化像素坐标来表达业务结构。

### 4.2 空方案与森林边界

- 方案没有任何树时，视图中心只显示一个空树槽位。
- 方案包含非空树时，树之间紧凑排列，不允许内部残留空树。
- 只有整个森林最左侧和最右侧允许出现创建独立树的空树槽位；它们属于边界入口，不计入树数量。
- 删除或剪切造成空树后立即归一化：中间空洞消失，连续非空树重新紧凑排列；最后一棵树被删除后回到单一中心空槽位。
- 左右边界槽位创建的新树分别插入森林首端或末端，顺序必须可预测。

### 4.3 非空树的叶端槽位

- 非空树的每个可继续扩展叶端都显示为空槽位，使用户无需先进入额外的“添加”命令。
- 叶端槽位是派生 UI，不自动写入节点、关系或撤销历史。
- 将帕鲁或完整分支拖到叶端槽位时，系统把当前叶端和拖入对象作为待组合的两个分支，查询正式无性别配方。
- 无结果时拒绝放置并保持原树不变；唯一结果可直接生成子代；双结果组合必须先让用户选择具体结果。
- 只有完整合法的三节点关系才进入领域模型和持久化。悬停、拖拽预览或尚未确认的双结果选择不得留下半条关系。
- 操作成功后，旧叶端槽位被新结构占用，并在新结果端生成新的叶端槽位。

该规则避免为了显示空槽位而引入“半个配种关系”或虚假节点。

## 5. 两个节点创建子代与树高对齐

### 5.1 基本流程

1. 用户选择两个不同节点实例，或把一个节点/分支拖到另一个可组合叶端槽位。
2. 两个实例可以代表同一种帕鲁，但不能是同一个实例。
3. 系统以无序亲本组合查询当前静态配方索引。
4. 无结果时不修改方案；唯一结果直接进入预览；多个结果时要求明确选择。
5. 计算两个所选结果节点各自来源子树的高度，以最长实际节点路径为准；空槽、视觉间距和缩放不计入高度。
6. 对齐两个结果节点所在层，在其下一层创建子代，并一次性提交节点复制、完整关系和森林顺序变化。
7. 整个操作只生成一个撤销记录、一次内容保存和一条成功状态消息。

### 5.2 高度相同

- 两个结果节点已经同层时，不增加虚假层级。
- 若两棵树均可在不产生共享节点的前提下直接合并，则复用当前节点实例。
- 任一节点已被其他后续分支占用时，复制其完整来源子树后再组合，避免一个实例拥有多个下游用途。

### 5.3 高度不同

- 把视觉上更高、结构上更短的来源子树深复制为新的节点和关系实例。
- 复制件的结果节点对齐到较深树的结果层；高度差通过布局层的垂直对齐表达，不创建“空白帕鲁”或无配方关系。
- 新子代位于两个已对齐结果节点的下一层。
- 原较短树继续保留；复制件参与新树。若较深树也不能安全原位参与，则同样复制，原树均保留。
- 所有复制节点使用新节点 ID，所有复制关系使用新关系 ID，但保留原 `palId`、`recipeIndex` 和可追溯来源。

### 5.4 严格树不变量

每次候选变更提交前必须验证：

- 节点和关系 ID 唯一且引用完整。
- 两个亲本是不同实例。
- 配方索引与两个亲本及子代完全一致。
- 每个子代最多一条生成关系。
- 每个节点实例至多参与一个下游分支；需要再次使用时复制来源子树。
- 不存在有向循环、重复完整关系或跨树共享节点。
- 失败时整体拒绝，不允许部分复制、部分删除或留下空洞。

## 6. 拖放与动态反馈

### 6.1 可拖对象

- “加入帕鲁”面板中的帕鲁可拖入空树槽位或合法叶端槽位；拖动属于创建实例，不从列表移除。
- 图内已有节点发起的结构拖动代表复用其来源分支；必要时按严格树规则复制，不执行自由坐标移动。
- 键盘和触屏必须提供与拖放等价的“选择目标槽位并放置”路径。

### 6.2 拖拽状态

拖拽期间槽位至少区分：默认、候选、当前悬停、非法、正在校验和提交成功/失败。动态效果应遵守以下边界：

- 仅合法候选槽位高亮；非法槽位变暗并提供可读原因。
- 当前悬停槽位可轻微放大、描边或显示插入预览，但不得引发布局持续抖动。
- 预览使用占位尺寸，放置前后不应导致整棵森林反复跳位。
- 遵守 `prefers-reduced-motion`；降低动态时仍保留边框、图标或文字等非颜色反馈。
- 拖拽离开、按 Escape 或放置失败时完整恢复，不产生历史、保存或成功提示。

### 6.3 禁止浏览器原生拖拽

- 节点容器、文字和图片在编辑器内不得被浏览器原生选中或拖走。
- 图片使用非原生拖拽语义；对编辑器范围内的原生 `dragstart` 做定向阻止。
- 自定义拖拽使用 Pointer Events 或等价受控机制，并在结束/取消时释放指针捕获。
- 不得全局禁用普通页面文本选择；限制只作用于配种图交互元素。
- Web 版拖动节点不得生成图片幽灵、地址拖拽或新标签页；Electron 行为必须一致。

## 7. 工具模式

### 7.1 光标模式

新的“光标”模式取代原单一“选择节点”工具，并作为默认编辑模式：

- 点击节点：选择或聚焦节点。
- 在空白视口按下并拖动：平移视口。
- 从可拖节点开始拖动：进入结构拖放，不把节点当作平移起点。
- 点击空白但未形成拖动：清除当前选择。
- Escape：取消当前拖动、候选关系或选择状态，按由内到外的顺序处理。

### 7.2 仅平移模式

原“平移画布”改名为“仅平移”，使用手形图标：

- 从空白、节点、连线或槽位任意位置开始拖动都只平移视口。
- 点击节点不改变选择，不发起结构拖动、关系创建或槽位放置。
- 进入模式时使用 `grab`，拖动中使用 `grabbing`。
- 平移不进入内容撤销栈，不触发节点/关系内容保存。

两个模式互斥，工具栏必须提供 Tooltip、可访问名称、非颜色激活状态和键盘操作。窄屏与触屏不得依赖 Hover 才能理解当前模式。

## 8. 固定快捷键

快捷键只在配种图编辑器处于活动上下文时生效，不提供用户配置。焦点位于文本输入、可编辑内容、原生选择器或模态对话框时，不拦截剪贴板和缩放按键。

| 快捷键 | 行为 | 规则 |
| --- | --- | --- |
| `Ctrl+C` | 复制 | 将当前选中的节点/完整结构写入图内结构化剪贴板；不复制视口和临时槽位 |
| `Ctrl+T` | 剪切 | 将选中结构写入图内剪贴板，并以单次可撤销事务从原位置移除；留下的森林立即归一化 |
| `Ctrl+V` | 粘贴 | 生成全新节点/关系 ID，在当前可见区域最近的合法空树槽位或已选目标槽位创建副本 |
| `Ctrl++` | 放大 | 以视口中心为锚点按固定步长放大；同时兼容主键盘 `Ctrl+=`/Shift 产生的 `+` 和数字小键盘加号 |
| `Ctrl+-` | 缩小 | 以视口中心为锚点按固定步长缩小，并兼容数字小键盘减号 |
| `Ctrl+滚轮` | 连续缩放 | 以指针所在内容坐标为锚点缩放，缩放前后该内容点保持在指针下方 |

补充规则：

- 缩放继续服从统一上下限；到达边界后不重复保存或提示成功。
- 每次按键缩放提交一次最终视口；连续滚轮在静默期结束后合并为一次视口保存。
- 复制、剪切和粘贴只处理 PalTools 结构化数据，不执行剪贴板中的 HTML、脚本或外部资源。
- 无选中、剪贴板为空或目标不合法时不修改方案，并提供简短可访问状态。
- 粘贴和剪切各自只形成一个撤销记录；粘贴后仍可再次粘贴同一内容。
- `Ctrl+T` 是本需求明确指定的剪切键，不自动替换为常见的 `Ctrl+X`。由于 Chromium 浏览器通常把 `Ctrl+T` 保留给“新建标签页”，实施前必须在支持的 Web 与 Electron 环境做可拦截性验证；Electron 必须支持，Web 若无法可靠覆盖则暂停键位替换并记录平台限制，不得静默声称已支持。
- 在编辑器活动且成功处理缩放快捷键时阻止浏览器页面级缩放，离开编辑器后恢复浏览器默认行为。

## 9. 左右图标菜单

- “加入帕鲁”改为左侧边缘图标按钮，打开左侧面板。
- 原“关系列表”（需求原文中的“关系列表3”按该名称理解）改为右侧边缘图标按钮，打开包含“已标记配方”和“当前方案关系”的右侧面板。
- 按钮可以隐藏常驻文字，但必须保留 Tooltip、`aria-label`、激活/展开状态和清晰焦点环。
- 图标不能只靠左右方向表达含义，应分别体现“添加帕鲁”和“配方/关系列表”。
- 桌面端面板可覆盖或占用预留安全区，但开合不得改变树的业务槽位顺序；计算适应视图时应考虑当前实际遮挡。
- 窄屏使用覆盖面板，同一时刻默认只展开一侧；Escape、遮罩点击和再次点击图标均可关闭。
- 关闭面板后图标入口仍可见，搜索与折叠状态是否保留需与当前“加入帕鲁”行为一致。

## 10. 查询页配方标记与右侧栏

### 10.1 工作流变化

- 输入亲代页面的单亲展开结果、双亲精确结果，以及输入目标子代页面的每张完整配方卡片，均把原“追加到配种图”按钮改为“标记配方”。
- 点击未标记配方时加入标记列表；再次点击同一按钮时取消标记。按钮必须显示可读的未标记/已标记状态，不只依赖颜色或图标变化。
- 标记操作不要求选择或创建当前方案，不创建节点、关系或槽位，不触发方案撤销栈及 IndexedDB 方案保存。
- 用户切换查询条件、分页、顶层页面或进入配种图后，标记仍在当前应用会话中保留。
- 首版标记为会话级状态：应用刷新、关闭或重启后可以清空；不写入 `.paltools-plan.json`，也不属于任何单一方案。

### 10.2 标记身份与顺序

- 使用当前数据集中的精确 `recipeIndex` 作为标记身份；相同配方从不同查询入口看到时必须共享同一标记状态。
- 重复标记是幂等操作，不得在右侧栏生成重复卡片。
- 同种亲本配方仍表示两个不同亲本实例；无序亲本展示顺序不改变配方身份。
- Katress 与 Wixen 的双结果按两个不同 `recipeIndex` 独立标记，不能把整个亲本组合误当成一条标记。
- 右侧栏按首次标记顺序稳定展示；取消后再次标记视为新的末尾项目。

### 10.3 右侧栏展示

- 右侧栏包含两个语义清晰的区域或标签：“已标记配方”和“当前方案关系”。两者不得混为同一种数据。
- “已标记配方”卡片显示完整 `亲本 A + 亲本 B → 子代`、本地图片及可访问文本，并提供取消标记操作。
- 查询页按钮状态与右侧栏实时同步；在任一位置取消后，另一位置立即反映。
- 没有标记时显示明确空状态；标记列表本身不得因没有当前方案而隐藏或禁用。
- 当前方案关系列表继续只反映已经存在于方案中的完整关系，不把标记误报为已加入方案。
- 本次需求只确认“标记”和“在右侧栏显示”。将标记配方真正转化为槽位树关系时，必须由 REQ-013 定义的独立、明确放置操作触发，不能恢复查询页直接写方案。

### 10.4 状态消息与可访问性

- 标记成功后按钮选中态和右侧栏内容就是持久到本次会话结束的主要反馈，不使用会跨页残留的“已追加到当前方案”提示。
- 可以使用短暂的“已标记/已取消标记”可访问状态，但离开查询页后不继续显示；状态消息不得暗示方案已经改变。
- 按钮具有 `aria-pressed` 或等价切换语义，Tooltip/可访问名称必须区分“标记此配方”和“取消标记此配方”。
- 键盘和触屏均可完成标记、进入右侧栏、浏览列表和取消标记。

该需求取代原 BUG-012 及 BUG-014 中“配方追加显示异常”的部分；BUG-014 只继续跟踪“直接加入帕鲁”的显示问题。

## 11. 缺陷修复验收口径

### BUG-013：导出过早显示成功

- 导出开始后显示“正在导出”，重复触发被禁用或合并。
- 序列化失败、文件 API 拒绝、用户取消或下载触发失败时不得显示成功。
- Electron 或可确认写入完成的文件 API：仅在写入 Promise 成功完成后显示“导出成功”。
- 普通 Web 下载若只能确认浏览器已接收 Blob/下载动作而无法确认磁盘落盘，状态文字必须是“已开始下载”，不得宣称“导出成功”。
- 成功、取消和失败状态均具有可访问消息，且不早于对应异步结果。

### BUG-014：直接加入帕鲁显示异常

由于当前描述未限定具体错位表现，编码前必须记录“从加入面板直接添加”的最小复现，包括方案初始状态、视口、侧栏状态、实际 DOM 几何和期望位置。

最低验收线：

- 直接加入后新节点占据明确合法槽位，并生成可继续扩展的叶端槽位。
- 新内容不会重叠、被工具栏/面板永久遮挡、落在不可到达区域、只在文本列表出现或刷新后才出现。
- 当前缩放、侧栏开合和四类要求视口下结果一致；必要时只做最小平移以保证新结构可见，不擅自重置用户缩放。
- 操作失败时图形、文本关系、撤销栈和持久化内容全部不变。

### BUG-015：仅平移导致频繁保存

- 指针移动期间通过帧调度更新视图，不写 IndexedDB。
- 一次从按下到释放/取消的平移手势至多保存一次最终视口；最终值未变化时零写入。
- `Ctrl+滚轮` 连续缩放按一次连续手势合并保存；内容保存与视口保存使用独立脏标记。
- 视口变化不进入节点/关系撤销栈，不刷新“方案内容已保存”提示。
- 切换方案或离开页面前只刷新尚未持久化且确实变化的最终视口。

### BUG-016：原生选字与拖出页面

- 见 6.3；此外需在拖动节点头像、名称、编号和空槽四个起点分别回归。
- 快速拖动、拖出编辑器后释放、按 Escape 取消和浏览器窗口失焦都必须正确清理拖拽状态。
- 回归期间不得出现文本选区、原生图片拖拽预览、地址拖拽或新标签页。

## 12. 状态、持久化与兼容

- 节点/关系内容、森林顺序、结构化剪贴板、瞬时拖放状态和视口状态分开管理。
- 会话级配方标记与方案内容分开管理；标记不进入方案自动保存、撤销栈、导入或导出。
- 结构化剪贴板默认只在当前应用会话内存在，不写入方案导出；不得要求系统剪贴板权限才能完成图内复制粘贴。
- 槽位布局由结构派生；新格式不应继续把自由 `x/y` 坐标作为布局真相。
- 视口仍可跨启动保存，但单独节流并在手势结束时提交。
- 当前 `.paltools-plan.json` 导入必须继续受大小、节点、关系、配方和无环校验保护。
- 若新严格树格式提升导出 Schema 版本，旧版坐标只作为兼容输入读取，不控制新槽位布局。
- 旧方案中存在“同一节点作为多个后续关系亲本”的 DAG 时，迁移应按稳定关系顺序深复制来源分支，使每个用途拥有独立实例；若展开后超过 1,000 节点/关系上限，则整体拒绝自动迁移并保留原数据，不允许静默截断。
- 导入/迁移完成后必须再次执行严格树不变量校验；失败不得覆盖原方案。

## 13. 可访问性与响应式

- 空槽位使用可聚焦按钮/放置目标语义，提供“在左侧创建树”“继续组合当前树”等上下文名称，不能只显示空框。
- 图标工具、左右菜单、拖放目标、成功/失败状态均可通过键盘和读屏使用。
- 查询页标记按钮和右侧已标记配方列表保持实时一致，并提供切换按钮语义。
- 图形树继续提供等价文本关系列表；复制、剪切、粘贴后两者同步更新。
- 视口内部缩放和平移不得带动背景页面，也不得造成页面级横向溢出。
- 至少覆盖 1440×900、1152×720、1366×768 和一个窄屏/低高度视口。
- 动态槽位效果遵守减少动态偏好；所有状态均有非颜色表达。
