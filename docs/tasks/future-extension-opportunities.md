# 未来扩展机会池

本文是候选方向池，不是需求清单、路线图承诺或当前行为说明。任何方向只有在明确用户问题、数据来源、最小范围和验收方式后，才可移入 [`todolist.md`](todolist.md)。

## 选择原则

候选能力应优先满足以下条件：

1. 解决玩家在“查找 → 比较 → 规划 → 验证”链路中的具体决策，而不是增加独立但低频的页面。
2. 默认离线、本机优先；不要求账号、云服务、遥测或应用启动后访问第三方。
3. 先复用当前 300 条图鉴、技能、掉落、数值和 44,851 条配方，再评估新增来源与素材。
4. 领域规则进入 `src/domain/*` 并可独立测试；图形界面始终提供等价文字结果。
5. 涉及新来源、地图、存档或版本差异时，先证明合法性、稳定性、可回滚性和独立校验能力。

## 推荐探索顺序

### 1. 主动技能反查

这是最小且数据完备的增量。第一版只需“选择技能 → 查看可学习帕鲁 → 按解锁等级或基础数值排序 → 打开图鉴详情”，不新增持久状态。成功标准是领域查询低于 100ms、完整结果可搜索、与图鉴详情交叉导航可恢复。

### 2. 掉落物来源反查

复用当前物品和掉落记录，补齐“知道物品、不知道谁掉落”的反向入口。第一版不推断地图位置或刷取效率；只呈现来源帕鲁、数量、概率和现有来源说明。若同名物品无法稳定消歧，应先修正数据身份再做 UI。

### 3. 工作队伍缺口分析

以“目标适性集合是否被覆盖”为核心，允许比较候选集合，但不记录个体数量、不模拟基地吞吐。第一版可从图鉴筛选结果临时加入比较栏，输出覆盖、最高等级和缺口三类文字结果。

### 4. 被动词条来源规划

只规划来源与配种连通性，不显示未经验证的继承概率。可在方案关系上标记“哪些起点提供哪些目标词条”，并在步骤列表中提示尚未覆盖的词条；必须保持现有 DAG、导入导出和失效关系语义。

### 5. 栖息地与只读存档

两者都应先做独立可行性调查。栖息地需确定来源、授权和离线表现；存档导入需建立版本矩阵、只读解析器、明确选取文件流程和失败隔离。未通过调查前，不应进入产品 backlog。

## 架构接缝

- 反查与比较逻辑优先扩展 `src/domain/pals.ts` 或新建单一职责领域模块，UI 不重新解释紧凑数据索引。
- 新静态数据必须进入 `pipeline/data` 的 build/validate 分工，并由 manifest 暴露版本与计数；禁止手改 `public/data/*.json`。
- 临时比较状态保持会话级；需要跨会话保存时，沿用版本化 localStorage 或 IndexedDB 边界，不创建账号依赖。
- CLI 与 Web 共享纯领域查询，但各自负责输入解析和输出；不能通过抓取 UI DOM 实现 CLI 功能。
- 新图形视图必须保留可复制、可搜索的文字或表格结果，并覆盖键盘、窄屏与减少动效模式。

## 进入 Todolist 前的门槛

每个候选方向至少补齐以下答案：

- 目标玩家在什么场景下遇到什么阻碍？
- 现有数据是否足够；若不足，来源、许可、更新频率与独立校验是什么？
- 第一版唯一主流程是什么，明确不做哪些相邻功能？
- 状态是会话级、本机持久化还是纯静态；损坏和版本不匹配如何恢复？
- 领域性能预算、最小测试、真实浏览器流程和 Electron smoke 各覆盖什么？
- 什么证据会导致该方向取消，而不是继续扩大实现？

通过这些门槛后，再把单一、可验收的需求写入 Todolist；本页面继续保留未确认方向，不承担实施跟踪。
