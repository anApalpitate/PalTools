## BUG-010：配种图性能与渲染结构优化

### 问题

当前配种图沿用通用节点画布的交互和渲染机制。节点数量增加后，平移、缩放、节点拖动和状态保存会触发过多布局、React 更新或边重绘，操作不够丝滑，直接影响主要工作流。

### 目标方案

- 将配种图明确约束为分层无性别森林：每个子代节点最多拥有一条生成关系，亲本位于上层、子代位于下层；同一节点可以继续参与多条后续配种关系。
- 优先采用森林专用场景结构，不再让通用画布负责全部布局。布局层按代数和兄弟顺序预先计算稳定槽位，并为可继续创建子代的位置预留“孔位”；创建、删除和合并只重排受影响分支。
- 推荐渲染结构为轻量 HTML 节点层、单一 SVG 连线层和统一视口变换层；避免每个节点/边各自维护高成本画布实例或在指针移动期间重建整张图。
- 节点位置、关系、选择、撤销/重做、导入导出和 IndexedDB 方案 Schema 保持兼容。允许在用户手动拖动后保存位置，但自动整理必须回到确定性槽位。
- 指针移动期间只更新内存中的视觉位置；拖动结束后再写入编辑历史并触发 500ms 自动保存，不能在每个 `pointermove` 上持久化方案。
- 若保留 React Flow 作为过渡实现，必须先通过受控更新、视口裁剪、节点/边 memo、批量状态提交和关闭无用交互能力达到性能门槛；未达到时切换到森林专用渲染器。

### 性能验收

- 建立 100、300、500 节点且含多棵树的固定基准方案，分别记录首次进入、自动整理、持续平移、滚轮缩放和单节点拖动。
- 目标桌面基线下，300 节点常用操作无肉眼可见停顿；500 节点持续平移/缩放目标不低于 50 FPS，拖动过程中不得出现持续超过 50ms 的主线程长任务。
- 单节点拖动不得触发整图领域校验、自动保存或全量布局；结束交互后方案仍能正确恢复、撤销和导出。
- 优化前后领域关系、文本关系列表和导入导出结果必须等价，不以删除既有编辑能力换取性能。

## BUG-011 / REQ-007：视口、缩放与工具反馈

### 缩放边界

- 所有缩放入口共用同一组常量，包括滚轮、触控板、工具栏按钮、程序化视口恢复和“适应画布”。
- 建议首版最大缩放值为 `1.5`，最小缩放值保持足以查看大型森林；恢复旧方案中超界的缩放值时必须安全钳制。
- 放大达到上限后按钮进入禁用状态，滚轮继续放大不再改变视口；缩小端采用相同规则。

### “适应画布”正确行为

- 只计算实际节点的联合包围盒，不把工具栏、侧栏、关系列表、隐藏节点或预留孔位计入内容范围。
- 使用当前真实画布可用区域计算视口；“加入帕鲁”侧栏和关系列表开合后再次执行时，结果必须基于变化后的尺寸。
- 在四周保留一致且可见的安全内边距，最终缩放值必须处于统一最小/最大边界内；单节点、超宽森林、超高森林和多棵离散树均不得被裁切。
- 空画布点击时恢复稳定的默认视口，不产生 `NaN`、无限缩放或突然跳转；连续点击结果应保持幂等。

### 工具与鼠标样式

- 选择/移动工具使用默认选择光标，悬停可拖节点时显示 `grab`，拖动中显示 `grabbing`。
- 平移工具在画布上显示 `grab`，按住拖动画布时显示 `grabbing`。
- 查询获取方式工具在可查询节点上显示帮助/查询型光标，在空白区域保持普通光标。
- 创建子代、合并、删除等不可执行状态使用禁用光标；工具切换后光标必须即时更新，不依赖下一次点击。
- 光标只是辅助反馈，按钮激活态、可访问名称和键盘操作继续保留。

## REQ-008：紧凑的配方追加入口

- 双亲精确结果、单亲展开结果和“获取目标帕鲁”的每张完整配方继续支持追加到当前方案，但按钮统一改为小型圆形或圆角方形 `+` 图标。
- 按钮的可访问名称固定为“追加到配种图”；鼠标 Hover 和键盘聚焦均显示同名 Tooltip，不使用仅鼠标可见的 `title` 作为唯一说明。
- 无当前方案或追加不可用时保留按钮位置并显示明确禁用态，Tooltip 解释需要先创建方案，避免卡片布局跳动。
- 点击后的节点创建规则、返回上下文和自动保存语义保持不变；连续误点应有清晰反馈，但不得静默复用已有节点。

## REQ-009：完全隐藏“加入帕鲁”侧栏

- 关闭侧栏后，侧栏 DOM 可保持挂载以保留搜索状态，但不得占据任何 Grid/Flex 固定列，画布必须扩展到全部可用宽度。
- 在画布左侧提供不占布局宽度的浮动打开按钮；按钮具备“打开加入帕鲁”可访问名称、Tooltip、键盘焦点和足够点击区域。
- 展开侧栏时保留当前搜索词和滚动位置；关闭或打开不得修改方案内容、节点坐标或撤销历史。
- 桌面端侧栏可覆盖画布或推动画布，推荐采用覆盖式面板以避免视口跳动；窄屏继续使用覆盖抽屉。无论采用哪种方式，关闭态必须完全释放宽度。
- 侧栏开合后，缩放、加入到视口中心和“适应画布”均以实际可见画布区域为准。

## 实施顺序与统一验收

1. 先建立性能基准和“适应画布”失败用例，避免结构替换后无法量化收益。
2. 抽离森林槽位布局、视口边界和包围盒为纯函数，再实施轻量渲染与交互更新策略。
3. 统一缩放常量、修复“适应画布”，并补齐工具光标状态。
4. 将侧栏改为完全隐藏/浮动恢复入口，再调整加入节点和适应画布的可用区域计算。
5. 最后替换配方追加按钮并统一 Tooltip/无障碍组件，集中执行完整回归。

统一验收覆盖 1440×900、1152×720、1366×768、窄屏和低高度；检查性能基准、节点/关系等价性、缩放边界、侧栏开合、工具光标、键盘路径、横向溢出、可见破图、控制台错误和第三方请求。EXE 只在本轮实现完成并要求更新桌面产物时执行一次。
