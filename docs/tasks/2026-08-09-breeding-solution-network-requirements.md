# 配种方案网简要需求

## 1. 产品决策

旧有以手工加入帕鲁、槽位放置、选择亲本、产生子代和编辑画布为核心的帕鲁配种图已经完整移除。后续拟使用“用户从查询结果中收集配方，系统自动构建配种方案网”的工作流替代。

本文件只描述尚未实施的 REQ-003 需求草案；当前产品仅提供双亲查子代和目标子代反查。

## 2. 用户目标

用户已经通过“双亲查子代”或“获取目标帕鲁”找到有价值的配方，希望低成本完成以下任务：

- 将查询结果中的具体配方加入同一个方案；
- 立即看清配方之间的上下游依赖、公共中间帕鲁和最终目标；
- 删除或替换配方后自动得到结构完整的新视图；
- 通过等价文本列表理解和执行方案，不依赖图形画布；
- 后续可在方案上记录完成状态、实际结果和词条信息，但第一阶段不推导词条继承概率。

## 3. 核心工作流

```text
在任一配种查询页得到结果
→ 逐条或批量收集具体 recipeIndex
→ 系统按配方集合去重并建立亲本—子代依赖
→ 自动分层、布局并适应可视区域
→ 用户聚焦目标、查看分支或移除关系
→ 系统重新计算方案网和等价文本步骤
```

查询结果是关系入口，已收集的精确配方集合是方案网的业务事实来源。节点、连线、层级和位置均由关系集合派生，用户不再直接创建节点、槽位、fork 或连线。

## 4. 方案网规则

- 每条关系保存精确 `recipeIndex`，同一配方在同一方案内只保留一次。
- 加入配方时自动带入两个亲本和一个子代；移除配方时重新计算仍被其他关系引用的节点。
- 视图默认只展示当前方案已收集的关系，不自动展开整个 44,851 条配方数据库。
- 自动布局按依赖代数分层，突出目标、缺失上游、公共中间帕鲁和多分支汇合点。
- 大型方案默认聚焦当前目标并折叠无关分支，提供适应视图、聚焦节点、展开和收起。
- 图形方案网始终提供完整等价文本关系列表；拖放或自由坐标编辑不得成为必需操作。
- 删除操作以“移除配方关系”为主，不允许通过直接删节点制造孤儿或不完整关系。
- 无法形成单一依赖链的配方仍可共存，界面应明确显示为多个连通分量，而不是强制伪造连接。

## 5. 查询页与方案页

查询卡片至少提供以下操作：

- 加入当前方案网；
- 从当前方案网移除；
- 批量加入当前筛选结果中的配方；
- 在方案网中定位已经加入的配方。

方案页至少提供以下能力：

- 创建、切换、重命名和删除方案；
- 查看自动生成的方案网和等价文本关系列表；
- 按目标帕鲁、配方或节点聚焦；
- 移除关系并立即重算；
- 查看配方来源于哪个查询入口；
- 在可访问性和窄屏场景下降级为关系卡片或步骤列表。

## 6. 已完成的旧功能退场基线

REQ-002 已完整移除所有只服务于手工配种图的内容：

- 手工加入帕鲁侧栏、槽位、节点选择、fork、产生子代和递归节点删除交互；
- 光标/仅平移/查询等旧画布编辑模式及其专用快捷键；
- 旧分层槽位领域命令、编辑历史和仅用于手工图的状态编排；
- 旧方案导入导出格式、CLI 方案校验及 IndexedDB 方案数据；
- 旧图专用测试、样式、任务说明和 canonical 配种图文档。

配种静态索引、双亲查子代、获取目标帕鲁、配方卡片和本地图片不属于移除范围。旧数据不迁移、不备份，应用启动时直接请求删除旧版配种图数据库。

## 7. 第一阶段边界

第一阶段不包含：

- 自动搜索最短或最优配种链；
- 根据已有帕鲁自动补全路线；
- 被动词条继承概率、个体值、数量、蛋糕或孵化成本推演；
- 自动把数据库中的替代配方扩展进方案；
- 多人协作、云同步或账号能力。

这些能力可以在关系驱动的方案网稳定后独立规划，不能阻塞基础替换。

## 8. 初步验收

- 三类查询结果（单亲、精确双亲、目标反查）使用同一方案收集状态，并按 `recipeIndex` 实时同步。
- 加入、重复加入、移除和批量加入均保持确定性，不能生成重复关系或孤儿节点。
- 任意关系集合都能生成稳定布局；同一输入重复计算得到相同层级和顺序。
- 至少 500 条已选关系下，交互和重新布局仍有明确进度或可接受响应，不阻塞查询页。
- 图形与文本关系完全等价；无图形操作也可检查并移除任意配方。
- 方案切换、刷新、导入导出和旧数据处理按最终确认的生命周期规则验收。
