# REQ-003 配种方案网需求

## 1. 文档状态

本文是 REQ-003 的完整产品需求和验收基线。需求已经完成确认，但功能尚未实现；实现完成并通过验收前，不得把本文描述为当前产品行为，也不得提前写入 canonical 产品或架构页面。

## 2. 背景与目标

当前配种页提供“亲代→子代查询”和“目标帕鲁查询”。用户可以找到具体配方，但缺少一个长期收集关系并自动组织为可执行方案的工作区。

REQ-003 增加与两个查询功能并列的“配种方案网”入口。用户从现有查询结果把精确配方加入关系背包，再从背包选择关系加入方案；系统依据关系集合自动生成稳定、清晰且美观的网络和等价文本步骤。用户不创建节点、连线或坐标，也不承担手工整理画布的工作。

## 3. 术语

- **配方**：两个无序亲本与一个子代构成的固定关系，以当前数据集中的精确 `recipeIndex` 标识。
- **关系背包**：跨两个查询入口共享、持久保存且不含重复配方的关系集合。
- **方案**：从关系背包选出的配方集合。方案只保存关系事实，节点、边、层级、连通分量、目标和坐标均由关系派生。
- **默认方案**：系统始终保留的内置方案，固定名称为“默认方案”，不可重命名或删除，只能清空内容。
- **自定义方案**：用户创建、重命名、清空或删除的方案；最多 20 个，不含默认方案。
- **合并视图**：同一帕鲁物种只显示一个节点，节点聚合全部上下游关系。
- **实例视图**：同一帕鲁可按配方中的不同出现位置显示为多个实例节点，便于拆解复杂路径；底层配方集合不变。

## 4. 产品范围

### 4.1 本阶段包含

- 新增与两个查询入口并列的“配种方案网”标签。
- 在亲代→子代查询和目标帕鲁查询的每个配方结果上提供“加入关系背包”。
- 提供持久化、去重、搜索、特色过滤、排序、单条移出和批量移出的关系背包。
- 在方案网页面侧栏常驻展示关系背包。
- 从关系背包单选或多选关系加入当前方案，加入后背包内容保持不变。
- 提供一个默认方案和最多 20 个自定义方案。
- 根据方案关系自动计算网络、文本步骤和关系列表。
- 支持合并视图和实例视图切换。
- 提供本机持久化及完整工作区 JSON 导入导出。
- 覆盖 Web 与 Electron、桌面与窄屏、键盘和屏幕阅读器。

### 4.2 本阶段不包含

- 最短、最优或最低成本配种链搜索。
- 根据已有帕鲁自动补全方案。
- “已拥有帕鲁”状态及其推演。
- 配方完成/未完成状态。
- 个体数量、孵化时间、蛋糕成本、个体值或词条继承概率推演。
- 自动从数据库扩展替代配方。
- 手工创建节点、连线、分叉或自由坐标。
- 账号、多人协作、云同步、遥测或运行时联网。
- 旧手工配种图数据的恢复、迁移或兼容。
- 新手引导或示例方案。

## 5. 信息架构

配种页包含三个同级入口：

1. 亲代→子代查询；
2. 目标帕鲁查询；
3. 配种方案网。

前两个入口继续承担配方发现，第三个入口承担关系背包管理、方案组织和自动呈现。方案页不再提供另一套配方数据库搜索器，配方只能从前两个查询入口加入关系背包。

## 6. 核心用户流程

### 6.1 收集配方

```text
在任一查询入口得到配方
→ 点击配方卡片的“加入关系背包”
→ 系统按 recipeIndex 幂等加入
→ 卡片显示“已在关系背包”
→ 关系立即出现在方案网侧栏
```

查询卡片只负责加入，不承担移出操作。重复加入不会产生重复关系，也不会改变原加入时间。

### 6.2 管理关系背包

```text
进入配种方案网
→ 在侧栏搜索、过滤或排序关系
→ 单选或多选关系
→ 加入当前方案，或从背包单条/批量移出
```

从背包移出关系不会删除已经加入方案的同一关系；从方案移除关系也不会修改背包。两者是独立集合。

### 6.3 构建与修改方案

```text
选择当前方案
→ 从关系背包选择一条或多条关系加入
→ 系统去重并重算节点、边、目标、层级和布局
→ 用户在图形网、步骤列表或关系列表中检查结果
→ 移除方案关系后系统立即重算
```

任何关系集合都允许进入方案。无法形成单一链路时，系统显示多个连通分量，不伪造连接。

### 6.4 管理方案

- 首次使用时默认方案已经存在并自动成为当前方案。
- 默认方案不可重命名、不可删除；清空必须二次确认。
- 用户可创建、切换、重命名、清空和删除自定义方案。
- 自定义方案名称为 1–40 个可见字符，允许重名；默认名为“方案 N”。
- 自定义方案达到 20 个后禁止继续创建，并给出明确说明。
- 删除或清空自定义方案必须二次确认；删除当前方案后切回默认方案。

## 7. 功能需求

### 7.1 查询入口与配方卡片

- `REQ-003-NAV-001`：三个配种入口必须使用同级导航语义和一致的键盘操作。
- `REQ-003-BAG-001`：亲代→子代的单亲结果、精确双亲结果以及目标帕鲁反查结果中的每张配方卡片都必须支持加入关系背包。
- `REQ-003-BAG-002`：已加入的卡片必须显示非颜色的可见状态，并阻止重复提交。
- `REQ-003-BAG-003`：查询输入、筛选、分页或标签切换不得清空关系背包。

### 7.2 关系背包

- `REQ-003-BAG-004`：背包以精确 `recipeIndex` 去重，同一关系最多出现一次。
- `REQ-003-BAG-005`：背包自然上限为当前数据集配方总数，不设置更小的任意产品上限。
- `REQ-003-BAG-006`：搜索框沿用现有查询的身份搜索体验，可匹配两个亲本或子代的中文名、英文名、内部 ID 和图鉴号。
- `REQ-003-BAG-007`：特色过滤以小型图标按钮呈现，第一阶段至少提供“仅看未加入当前方案”和“排除自交配方”。
- `REQ-003-BAG-008`：图标过滤按钮必须有可见提示、可访问名称、按下状态和非颜色状态标识。
- `REQ-003-BAG-009`：排序只提供配方编号与加入时间两个字段，均支持正序和倒序；默认按加入时间倒序。
- `REQ-003-BAG-010`：背包支持单条移出及多选后批量移出，批量移出前显示数量并要求确认。
- `REQ-003-BAG-011`：搜索、过滤和排序只改变展示，不改变背包关系、选中项或加入时间。
- `REQ-003-BAG-012`：将已在当前方案中的关系从背包移出时，方案关系继续保留。

### 7.3 方案关系

- `REQ-003-PLAN-001`：默认方案固定存在，其系统身份与显示名称不依赖数组位置。
- `REQ-003-PLAN-002`：方案以 `recipeIndex` 去重；重复加入为无副作用的幂等操作。
- `REQ-003-PLAN-003`：用户可从背包单选或多选关系加入当前方案，操作完成后背包不变。
- `REQ-003-PLAN-004`：用户可从图形网、步骤列表或关系列表移除方案关系；移除后背包不变。
- `REQ-003-PLAN-005`：清空方案只清除该方案的关系，不清除关系背包或其他方案。
- `REQ-003-PLAN-006`：系统自动把“只作为子代、不作为任何方案关系亲本”的节点识别为目标；一个方案可以有多个目标。
- `REQ-003-PLAN-007`：无关关系以多个连通分量共存，各分量必须稳定排序并分别展示目标。
- `REQ-003-PLAN-008`：当前方案切换后，侧栏的“未加入当前方案”过滤和关系选中状态必须按新方案重算。

### 7.4 自动视图

- `REQ-003-VIEW-001`：方案提供图形网、步骤列表和关系列表，三种视图消费同一关系集合并具有等价的关系数量和移除能力。
- `REQ-003-VIEW-002`：默认打开步骤列表；应用记住用户最后选择的视图。
- `REQ-003-VIEW-003`：图形网默认从左到右，基础亲本在左、最终目标在右。
- `REQ-003-VIEW-004`：布局优先减少边交叉、突出目标和公共中间节点、保持同层对齐，并尽量压缩无意义空白。
- `REQ-003-VIEW-005`：相同关系集合、节点模式和视口输入必须得到确定的层级、节点顺序、关系顺序和坐标。
- `REQ-003-VIEW-006`：用户可在合并视图与实例视图间切换；切换只改变派生显示，不修改关系背包或方案。
- `REQ-003-VIEW-007`：用户不能拖拽并保存节点坐标，也不能直接创建或删除节点和连线。
- `REQ-003-VIEW-008`：大型方案默认聚焦当前目标并折叠非相关分支，提供展开、收起、适应视图和按帕鲁定位。
- `REQ-003-VIEW-009`：没有唯一目标时，系统选择稳定排序后的第一个目标作为初始聚焦，但始终显示目标切换入口。

### 7.5 文本步骤与关系列表

- `REQ-003-TEXT-001`：步骤按基础亲本到最终目标的依赖顺序排列。
- `REQ-003-TEXT-002`：每步至少显示序号、两个亲本、子代、前置步骤和配方编号。
- `REQ-003-TEXT-003`：无法按单链表达的关系按连通分量和并行分支分组，不得丢失关系。
- `REQ-003-TEXT-004`：关系列表提供与图形网等价的搜索定位和移除操作。
- `REQ-003-TEXT-005`：用户可以复制完整纯文本步骤；复制不依赖图形网可见状态。

## 8. 数据与持久化模型

### 8.1 关系快照

每个持久化关系至少包含：

- `recipeIndex`；
- `parentAId`；
- `parentBId`；
- `childId`；
- 首次加入背包时的 `datasetVersion`；
- 背包加入时间 `addedAt`。

`recipeIndex` 是当前数据集内的唯一身份；亲本和子代快照用于数据版本变化后的完整性检查和失效展示，不创建第二套关系身份。

### 8.2 工作区

持久化工作区至少包含：

- 工作区 `schemaVersion`；
- 保存时的 `datasetVersion`；
- 去重的关系背包；
- 固定身份的默认方案；
- 最多 20 个自定义方案；
- 当前方案 ID；
- 最后使用的视图与节点模式。

方案只保存去重的关系引用、名称、创建时间和更新时间，不保存派生节点、边、层级、折叠结果或坐标。

### 8.3 数据版本变化

- 载入持久化关系时，系统必须验证当前 `recipeIndex` 解码后的三元组是否仍与快照一致。
- 无法解析或三元组不一致的关系保留为失效关系，不得误绑定到新配方。
- 失效关系显示原快照、数据版本和明确警告，可从背包或方案中移除，但不参与有效网络布局。
- 有效关系和失效关系均计入各自集合的总数，界面必须分别显示计数。

### 8.4 导入导出

- 导出文件包含工作区 Schema、应用版本、数据版本、导出时间、关系背包、全部方案和用户视图偏好。
- 导入是完整工作区恢复：先校验和预览数量，再经用户确认替换当前工作区。
- 文件损坏、Schema 不支持、缺少默认方案、关系重复或自定义方案超过 20 个时拒绝导入，当前数据保持不变。
- 数据版本不同但结构合法时允许导入，并按 8.3 节逐条标记有效或失效关系。
- 导入成功后必须仍恰好存在一个不可删除的默认方案。

### 8.5 存储

- Web 与 Electron 共用 IndexedDB 持久化模型。
- 所有写操作采用完整事务；失败时保留操作前状态并向用户显示可恢复错误。
- 功能在离线环境下完整可用，不产生第三方运行时请求。

## 9. 界面与响应式要求

### 9.1 桌面

- 方案页主体由关系背包侧栏和方案内容区组成。
- 侧栏必须可以独立滚动，不因网络画布缩放或平移而移动。
- 方案内容区包含方案切换与管理、视图切换、节点模式切换、目标聚焦和当前视图。
- 空默认方案显示关系背包选择提示；关系背包为空时引导用户前往两个查询入口，但不启动新手教程。

### 9.2 窄屏

- 默认显示步骤列表或关系卡片，不强制用户在小屏操作图形网。
- 关系背包通过可明确打开和关闭的抽屉或面板呈现，保留搜索、过滤、排序、多选和批量移出能力。
- 页面、抽屉和内部列表不得产生意外横向滚动。

## 10. 可访问性

- 三个同级入口、方案切换、关系背包、视图切换和节点模式切换使用正确的标签页、列表、按钮或单选语义。
- 所有关键流程可仅使用键盘完成：加入背包、搜索过滤、排序、多选、批量移出、加入方案、切换方案、切换视图、聚焦目标和移除方案关系。
- 图标按钮提供中文可访问名称、可见提示及按下状态，不以颜色单独表达状态。
- 图形网提供结构化文字摘要；屏幕阅读器至少能获知父本、子代、配方编号、目标和前置依赖。
- 动画和自动视图过渡遵守 `prefers-reduced-motion`。
- 颜色对比度沿用当前主题验收：正文至少 4.5:1，焦点、控件边界和选中状态至少 3:1。

## 11. 非功能要求

### 11.1 性能

在包含 500 条有效方案关系的验收 fixture 下：

- 单条加入、单条移除及背包过滤/排序的用户可见响应不超过 300ms；
- 网络重新计算和布局不超过 1 秒；
- 超过 300ms 的操作显示忙碌状态，布局计算期间不得阻塞查询页输入；
- 关系背包和关系列表使用可承载大集合的渲染策略，不一次挂载全部数据行。

### 11.2 确定性与完整性

- 同一输入重复计算必须得到相同结果。
- 任一有效配方必须同时完整包含两个亲本和一个子代，不生成孤儿节点或半条边。
- 图形网、步骤列表和关系列表的有效关系集合必须完全一致。
- 搜索、过滤、排序、折叠和聚焦不得修改持久化关系。

### 11.3 平台与离线

- Web 和 Electron 使用相同领域规则和存储 Schema。
- 运行时不得访问第三方服务；断网不影响背包、方案、布局、导入或导出。

## 12. 验收标准

### 12.1 查询与关系背包

1. 在亲代→子代的单亲结果、精确双亲结果和目标帕鲁结果中加入配方后，三个入口立即显示一致的“已在背包”状态。
2. 对同一 `recipeIndex` 重复执行加入，背包仍只有一条关系，首次加入时间不变。
3. 背包搜索能匹配任一亲本或子代身份；“未加入当前方案”和“排除自交”过滤可组合使用。
4. 配方编号与加入时间排序均支持正倒序，结果稳定。
5. 批量移出只删除用户选中的背包关系，不删除任何方案关系。

### 12.2 方案生命周期

6. 新工作区自动创建默认方案；任何操作后都不能删除或重命名它，但可以确认后清空。
7. 可创建最多 20 个自定义方案；第 21 个创建请求被拒绝且已有方案不变。
8. 从背包批量加入方案后，方案内无重复关系，背包内容保持不变。
9. 从方案移除关系或清空方案后，背包与其他方案保持不变。
10. 删除当前自定义方案后自动切换到默认方案。

### 12.3 网络与文本

11. 同一关系集合在合并视图和实例视图中具有相同配方数量；切换模式不产生持久化关系变更。
12. 多个分支共享中间帕鲁时，合并视图只显示一个物种节点，并保留全部上下游关系。
13. 包含多个无关集合的方案显示多个连通分量及其各自目标，不生成虚假连接。
14. 图形网、步骤列表和关系列表对任一 fixture 的有效 `recipeIndex` 集合完全相等。
15. 移除任一方案关系后，三个视图、目标和连通分量立即一致重算。

### 12.4 持久化与异常

16. 刷新 Web 页面或重启 Electron 后，背包、方案、当前方案和视图偏好恢复一致。
17. 完整导出后清空本机数据，再导入文件可恢复同一工作区。
18. 导入失败不部分覆盖当前工作区。
19. 数据版本变化导致三元组不匹配时，关系显示为失效且不参与布局，不会被当前 `recipeIndex` 指向的新配方替代。

### 12.5 可访问性、响应式与性能

20. 仅使用键盘可完成从查询配方加入背包到加入默认方案、查看步骤及移除关系的完整流程。
21. 1440×900、1152×720、1366×768 和 390×844 视口下无意外横向滚动，关系背包和主内容均可独立访问。
22. 500 条有效关系 fixture 满足 11.1 节响应时间，操作期间查询页仍可响应输入。
23. Web 与 Electron 在断网环境下完成主流程且没有第三方运行时请求。

## 13. 实现边界

- 关系去重、过滤、排序、目标识别、连通分量、两种节点语义、文本拓扑顺序和确定性布局输入必须位于纯领域层并有单元测试。
- React 层只负责状态编排和呈现，不重新实现配方解码或图关系规则。
- IndexedDB 仓储必须独立于 React，并对 Schema、事务失败、损坏数据和数据版本变化进行测试。
- 派生图形状态不进入持久化 Schema；重新打开方案必须从关系事实重建。
- 图形组件不可成为唯一可用界面，文字步骤和关系列表是正式验收面。
