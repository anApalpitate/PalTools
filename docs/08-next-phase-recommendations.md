# 第四阶段功能建议

第三阶段建议的反向配种、起点集合、多代路径、技能和掉落已经完成。下一阶段建议围绕“保存、比较、解释”增强现有价值。

| 优先级 | 功能 | 用户价值 | 成本 | 数据风险 |
| --- | --- | --- | --- | --- |
| P0 | 保存多套路线方案与目标收藏 | 不必反复重建常用计划 | 中 | 低 |
| P0 | 多条路径成本比较 | 在代数相同情况下理解取舍 | 中高 | 低 |
| P1 | 路线 JSON/图片导出与导入 | 分享路线且不接触存档 | 中 | 低 |
| P1 | 数据版本差异报告 | 来源升级时明确哪些配方/字段变化 | 中 | 低 |
| P2 | 掉落物、技能反向检索 | 复用第三阶段已采集内容 | 低 | 低 |
| P2 | 栖息地与地图展示 | 提升收集效率 | 高 | 中高 |
| P3 | 存档只读导入 | 自动生成已拥有集合 | 高 | 高 |
| P3 | 被动继承规划 | 接近实际培养流程 | 很高 | 高 |

## 推荐主题：路线管理与成本比较

1. 为路线和起点集合提供本地命名、复制、删除与导入导出。
2. 在同一目标下生成有限数量的稳定候选，而非无限枚举。
3. 对每条路线解释代数、配种节点数、不同中间帕鲁数和起点覆盖。
4. 允许用户自定义权重，但保留当前确定性默认排序。
5. 导出格式包含数据集版本，导入旧路线时明确提示差异。

## 风险约束

- 不把“配种参数较优”误写为游戏内成本最低；当前没有蛋糕、孵化时间或个体数量模型。
- 存档导入必须只读、显式选择文件、文档化支持版本，并与路径算法分层。
- 栖息地和地图素材在公开发行前需要单独检查来源和再分发权利。
- 更新检查必须由用户主动触发，默认仍完全离线、零遥测。
