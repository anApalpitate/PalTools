# 配种图分层槽位运行逻辑

> 最终实现决策（2026-08-01）：本文件中早期草案若提到 Ctrl+T、Ctrl+X 或剪切，均以当前实现为准：本阶段只有 Ctrl+C、Ctrl+V、Ctrl++、Ctrl+- 和 Ctrl+滚轮，不实现剪切。`layers[].nodeIds` 是唯一的行和顺序来源，层对象不保存冗余 `row` 字段；v1 数据直接清除，不做迁移。光标模式为选择加空白平移，仅平移模式不选择节点。删除使用后代闭包，并对节点和关联线使用红色预览/退出动画。

## 1. 文档定位

本文是 REQ-010–REQ-013 的详细实现逻辑，覆盖“按代数分行、按槽位排列、相邻插入和节点配种”的层次图方案。

总原则：

- 图形结构由逻辑行、行内节点顺序和配种关系组成。
- 不保存自由像素坐标，不把画布位置当成业务数据。
- “空槽位”是可交互的派生目标，不是持久化的空节点。
- 节点复制、槽位插入、fork 和产生子代必须通过一个原子事务完成。
- 任何失败、取消或非法操作都不能留下半个节点、半条关系或临时空洞。

原专项需求文档只保留需求范围、完成基线和验收入口；本文是分层槽位图的唯一详细逻辑来源。

## 2. 核心概念

### 2.1 分层图

配种图由逻辑行组成：

- `row = 0` 是最初的节点行；
- 子代必须位于父节点所在行的下方；
- 行号越大表示越靠后的计划代次；
- 同一行内节点具有稳定的从左到右顺序；
- 视口缩放和平移不改变行号和顺序。

一个节点可以是独立加入的节点，也可以是关系生成的子代。独立节点允许出现在用户选择的任意已有行中，因为它表示“计划在该代使用的帕鲁实例”，而不是必须已经具有上游亲本。

### 2.2 节点实例

节点实例包含：

- 唯一 `id`；
- `palId`；
- `row`；
- 行内顺序 token 或节点 ID 顺序；
- 来源，例如 `manual`、`fork`、`child`、`import`；
- 可选 `forkOf`，用于追溯 fork 来源。

同一个 `palId` 可以存在多个节点实例。节点实例是配种关系的实际参与者，不能用 `palId` 代替节点 ID。

### 2.3 关系

关系包含：

- 两个不同的亲本节点 ID；
- 一个子代节点 ID；
- 精确 `recipeIndex`。

关系必须满足：

- 子代行号大于两个亲本行号；
- 子代最多拥有一条生成关系；
- `recipeIndex` 与亲本、子代完全匹配；
- 不存在环；
- 关系引用的节点必须存在。

### 2.4 槽位

槽位分为：

- 空图槽位：空方案中的第一个创建入口；
- 左插入槽位：某节点左侧的创建入口；
- 右插入槽位：某节点右侧的创建入口；
- 组合槽位：两个节点之间或节点下方用于产生子代的候选入口；
- fork 预览槽位：系统为满足邻接而临时展示的复制位置。

槽位只在当前操作需要时派生，不保存空节点。

## 3. 持久化结构

### 3.1 推荐 Schema v2

为了避免把像素坐标当作结构真相，方案 v2 应保存逻辑行顺序：

```ts
type BreedingLayerV2 = {
  nodeIds: string[]
}

type BreedingPlanV2 = {
  schemaVersion: 2
  layers: BreedingLayerV2[]
  nodes: BreedingGraphNode[]
  relations: BreedingRelation[]
  viewport: GraphViewportV1
  name: string
  createdAt: string
  updatedAt: string
}
```

`layers[].nodeIds` 是每行唯一的业务顺序来源。v2 不读取旧版节点的 `position.x/y` 作为布局真相；旧版数据不进入 v2 的布局计算。

### 3.2 派生索引

编辑器初始化或结构变更后，建立以下内存索引：

- `nodeById`：节点 ID 到节点；
- `rowByNodeId`：节点 ID 到行号；
- `indexByNodeId`：节点 ID 到行内索引；
- `parentsByNodeId`：子代到亲本；
- `childrenByNodeId`：亲本到直接子代；
- `relationByChildId`：子代到生成关系；
- `rowBounds`：各行的最小/最大槽位范围。

这些索引只在一次变更后重建或增量更新，不在 React 渲染期间重复扫描完整方案。

### 3.3 旧版数据处理

本阶段不实现 v1 到 v2 的迁移，也不保留旧版数据作为兼容输入：

- 应用初始化时检测持久化方案的版本；发现 v1 或无法识别的旧版方案时，直接清除旧版方案记录和当前方案指针；
- 清除完成后立即创建一个空的 v2 工作区，不尝试从旧节点、旧关系或旧坐标恢复内容；
- 清除动作只针对已识别的旧版持久化数据，不删除当前已有的 v2 数据；
- v1 导入文件不支持迁移，导入时明确拒绝且不覆盖当前 v2 方案；
- 清除或初始化失败时不得写入半成品，保留可重试的错误状态并阻止编辑器进入不完整方案。

## 4. 创建节点与相邻插入

### 4.1 空图创建

空方案只显示一个居中的空图槽位。向其中放入帕鲁时：

- 创建一个独立节点；
- 放入第 0 行；
- 生成左右两个可插入槽位；
- 生成一个可用于产生子代的下方组合入口；
- 产生一次内容变更和一次撤销记录。

### 4.2 非空图创建

创建目标必须绑定已有节点和方向：左侧或右侧。无需先存在物理空位。

逻辑操作是对行数组执行插入：

```text
row[2] = [A, B, C, D, E]
在 C 左侧创建 C' 后：
row[2] = [A, B, C', C, D, E]
```

现有节点只是获得新的派生显示位置，节点 ID、关系、行号和相对顺序不变。

### 4.3 插入选择与扩容

如果目标侧紧邻位置已经被占用：

- 用户仍然可以在该侧执行插入；
- 目标行数组在目标节点前或后插入新节点；
- 新节点之后的节点整体顺移一个逻辑槽位；
- 不创建边缘临时节点；
- 不覆盖、删除或 fork 目标节点；
- 布局函数重新计算所有受影响行的像素位置。

左/右方向必须明确：

- 拖放到节点左侧热区表示左插入；
- 拖放到节点右侧热区表示右插入；
- 键盘菜单分别提供“在左侧创建”和“在右侧创建”；
- 点击节点中心不隐式选择方向。

### 4.4 可进行的创建操作

- 在空图槽位创建第一个节点。
- 将加入面板的帕鲁拖到节点左侧插入热区。
- 将加入面板的帕鲁拖到节点右侧插入热区。
- 在节点的左侧或右侧执行键盘创建命令。
- 在已占用的相邻位置执行插入式扩容。
- 预览受影响的行和节点移动范围。
- 在提交前取消操作或按 Escape。
- 创建完成后撤销整个插入事务。

### 4.5 拖放目标反馈

从加入列表拖入新帕鲁时，空槽位和可插入热区必须提供明确的动态反馈：

- 拖拽进入合法空槽位后，空槽显示品牌色的呼吸/脉冲边框、轻微光晕和占位内容浮动效果；动画只作用于目标槽位，不推动其他节点；
- 拖拽在同一行已占用位置上方时，显示将要插入的空槽和受影响节点的临时重排预览；预览目标保持稳定，不因每一帧鼠标移动重复创建业务状态；
- 合法目标与非法目标必须有不同状态：合法目标突出显示，非法区域降低透明度并显示不可放置光标，不显示“可放置”动画；
- 放置成功后先完成一次短暂的目标确认效果，再切换为正式节点；取消、离开编辑器、窗口失焦、拖出边界或放置失败时，所有动态状态立即清除；
- 拖放预览和动画均属于临时 UI 状态，不写入方案、不进入撤销历史、不触发保存；
- 支持 `prefers-reduced-motion` 时，呼吸和位移动画降级为静态高亮、边框变化或短暂颜色变化，但仍必须能识别目标槽位。

## 5. 产生子代

### 5.1 统一事务

产生子代始终按以下顺序执行：

- 锁定两个节点实例；
- 检查是否为同一个节点、是否会形成环、是否允许跨行组合；
- 查询无序配方；
- 无结果则结束且不改方案；
- 多结果则等待用户选择 `recipeIndex`；
- 计算父节点的目标行和行内位置；
- 必要时插入逻辑槽位或生成 fork 预览；
- 生成子代节点和关系；
- 一次性执行关系校验、结构提交、撤销记录和保存标记。

候选阶段只允许显示预览，不写入节点数组、关系数组或 IndexedDB。

### 5.2 同层且相邻

若两个节点在同一行且中间没有节点：

- 子代目标行是父节点行号加一；
- 子代的水平锚点是两个父节点槽位的中点；
- 如果目标行对应位置可用，直接插入子代；
- 如果目标行位置被占用，在目标行插入一个逻辑槽位；
- 重新布局连线，但不改变两个父节点。

### 5.3 同层但不相邻

不直接连接两个远距离节点，而是先创建一个同层 fork：

- 计算两个节点左右两侧的插入成本；
- 优先在影响节点较少的一侧插入 fork；
- 成本相同则使用用户拖拽方向；无方向时固定选择右侧；
- fork 节点复制 `palId`，使用新 ID，行号与目标节点相同；
- 原节点和原关系保持不变；
- fork 后两个参与组合的节点成为相邻节点；
- 在下一行的对应位置生成子代。

### 5.4 不同层

不同层时使用较深父节点的行作为组合行：

- 将较浅父节点 fork 到较深父节点所在行；
- fork 节点放置在较深父节点左侧或右侧；
- 若目标侧被占用，直接插入逻辑槽位；
- 两个父节点完成同层邻接后，在下一行生成子代。

fork 只复制节点实例，不复制其上游关系。它表示“在当前计划代次增加一个可用的同种帕鲁实例”，不会制造虚假中间代。

### 5.5 不同层、不相邻且没有空位

这种情况不再创建边缘 `F`。采用“目标侧插入 + fork”两步事务：

- 选择较深父节点作为锚点；
- 根据用户拖拽方向确定左插入或右插入；
- 在锚点所在行直接插入一个逻辑槽位；
- 将较浅父节点 fork 到新槽位；
- 在下一行按两个父节点中点插入子代；
- 重新计算受影响行的布局和连线。

因此，行内没有预先存在的空位不是失败条件。只要没有达到数据上限，系统总能通过插入逻辑槽位完成操作。

### 5.6 产生子代的可进行操作

- 选中两个节点并点击“产生子代”。
- 从一个节点拖动到另一个节点的左侧或右侧组合热区。
- 将加入面板中的帕鲁拖到组合热区。
- 在多结果候选中选择一个具体子代。
- 取消候选关系、按 Escape 或点击取消。
- 预览 fork、插槽和子代位置后确认提交。
- 对已参与其他关系的节点再次配种，由系统创建新的 fork 实例。
- 对已存在子代的目标位置执行局部插入，而不是覆盖已有子代。

## 6. 删除与完整性

删除采用后代闭包：删除节点本身，并递归删除沿关系向下可达的所有子代及相关关系。

### 6.1 删除区域反馈

删除确认阶段和删除提交阶段都必须明确反馈完整的影响范围：

- 删除预览区域由待删除节点的后代闭包和这些节点之间的全部连接线组成；多选删除时先合并闭包，避免同一节点或连线重复计算；
- 待删除区域以红色半透明覆盖、红色边框/连线高亮和轻微脉冲效果呈现，节点、连接线和区域边界必须同时变红，不能只给被点击的节点变色；
- 删除确认弹窗或操作栏同步显示待删除节点数、连接线数和后代范围；红色动画只表达“即将删除”，不表示普通选中状态；
- 用户取消、按 Escape、点击其他操作或删除校验失败时，红色预览立即恢复，原结构不变；
- 确认删除后先提交一次原子结构事务，再保留被删除区域的红色退出快照约 180–240ms 后淡出；退出动画期间不得重新参与布局、选择、拖放或保存；
- 删除失败时不得播放成功退出动画，不得清除待删除状态，并保留可读错误以便重试；
- 支持 `prefers-reduced-motion` 时取消脉冲和位移动画，保留静态红色覆盖、边框、连线和文字提示。

- 删除父节点不会删除其亲本、兄弟节点或其他分支。
- 删除后失去父关系的幸存节点变为合法独立节点，不是断裂关系中的孤儿。
- 不自动重新接线、不凭空生成替代配方、不自动 fork 幸存节点。
- 删除后清理空行，保留幸存节点的行内相对顺序。
- 删除全部节点后恢复空图中心槽位。
- 多选删除先合并所有后代闭包，再执行一次原子删除。
- 删除确认显示递归删除范围和关系数量。
- 删除、剪切和撤销都必须恢复/移除完整的节点和关系集合。

## 7. 布局算法与性能

### 7.1 布局输入

布局只读取：

- `layers` 的行顺序；
- 节点宽高常量；
- 关系端点；
- 当前面板安全区；
- 当前视口缩放和平移。

不读取旧像素坐标作为业务输入。

### 7.2 布局步骤

- 按行数组为节点分配基础槽位中心点；
- 根据父节点中点为子代计算期望水平位置；
- 对同一行发生冲突的节点按稳定顺序向两侧展开；
- 只在必要时扩大受影响行的槽位间距；
- 通过父子约束检查连线是否发生不可接受的反向穿越；
- 以确定性 tie-breaker 解决相同位置；
- 生成节点矩形、边路径、插入热区和组合热区。

### 7.3 性能边界

- 结构变更时重建索引为 O(V + E)。
- 行内插入为 O(W)，其中 W 是目标行节点数。
- 布局只对结构签名变化时重新计算；纯视口变化不重算布局。
- 拖拽预览使用临时布局，不写方案、不触发 React 全量状态提交。
- 视口拖动继续使用变换层直接更新；结构布局不参与每一帧计算。
- 目标规模 500 个节点时，结构命令和布局应保持在交互可接受范围内。

## 8. 交互状态机

### 8.1 光标模式

- 空白按下后超过移动阈值进入平移。
- 节点按下后超过移动阈值进入 fork/组合拖放。
- 节点点击只改变选择，不触发创建。
- 左右插入热区明确显示“左侧创建”或“右侧创建”。
- 空白点击清除选择。
- Escape 按“候选配方 → 拖放 → 插入目标 → 选择”顺序取消。

### 8.2 仅平移模式

- 任意位置拖动只平移视口。
- 节点、热区和连线不改变选择或结构。
- 使用 `grab`/`grabbing` 光标。
- 不进入内容历史和结构保存。

### 8.3 临时状态

临时状态包括：

- 当前选中节点；
- 当前插入方向；
- 当前组合目标；
- 当前 fork 预览；
- 当前候选配方；
- 当前拖拽来源和目标；
- 当前删除预览和删除退出快照；
- 当前键盘剪贴板。

这些状态不写入方案导出，不触发结构保存，取消后全部清理。

## 9. 快捷键与左右菜单

快捷键和左右菜单继续遵循原需求，但其目标必须改为分层槽位对象：

- `Ctrl+C` 复制当前焦点节点的帕鲁；
- `Ctrl+V` 粘贴到当前插入/组合槽位，无目标时粘贴到右侧扩容位置；
- 本阶段不实现 `Ctrl+T`、`Ctrl+X` 或剪切快捷键，递归删除通过删除按钮完成；
- `Ctrl++`、`Ctrl+=`、`Ctrl+-` 和 `Ctrl+滚轮`只改变视口；
- 左侧图标打开加入面板；
- 右侧图标打开已标记配方和当前关系面板；
- 面板开合不改变行数组和槽位顺序；
- 窄屏同时只展开一侧。

## 10. 事务与错误处理

所有结构命令使用统一事务：

```text
读取当前快照
→ 计算候选结构
→ 校验节点、行、关系和配方
→ 生成新 ID
→ 更新 layers / nodes / relations
→ 运行完整校验
→ 提交一次状态、历史和保存修订
```

出现以下情况时整体回滚候选，不留下中间状态：

- 无配方；
- 多结果尚未选择；
- 目标槽位非法；
- 行扩容超过上限；
- 节点或关系数量超过限制；
- 产生环或重复子代；
- fork 失败；
- 保存失败。

保存失败不回滚页面中已经合法提交的结构，只保留 dirty、错误和待保存修订，以便重试。

## 11. 测试与验收

领域测试至少覆盖：

- 空图创建和第一行建立；
- 左插入、右插入、占用位置插入和行扩容；
- 插入后行内相对顺序；
- 同层相邻直接产生子代；
- 同层不相邻 fork；
- 不同层 fork 到较深行；
- 不同层、不相邻且没有空位时的插入 + fork；
- 子代位置冲突和下一行扩容；
- 同节点、环、重复子代、无配方和多结果；
