# 可行性与技术组合

## 1. 结论

当前方案可行，并已完成三个阶段的实现与本地数据构建。核心查询是纯静态数据和 TypeScript 算法，不需要服务器、数据库或运行时网络。

## 2. 技术组合

| 层 | 技术 | 用途 |
| --- | --- | --- |
| UI | React 19 + TypeScript + Vite | 图鉴、配种、管理员页面 |
| 图形树 | `@xyflow/react` | 离线路径画布、缩放、节点选择 |
| 路径计算 | Vite Web Worker + 纯 TypeScript | 动态规划、精确代数和无环构树 |
| 数据工具 | Node.js + TypeScript + tsx | 同步、导入、构建、校验 |
| HTML | cheerio | 服务端渲染公开页面解析 |
| Schema | zod | 外部边界与最终产物校验 |
| 测试 | Vitest + Testing Library + Playwright | 领域、组件和真实浏览器验收 |
| 桌面 | Electron + electron-builder | Windows x64 便携 EXE |

## 3. 为什么使用静态 JSON

300 个图鉴条目和 44,851 条配方可以直接放入本地文件。Schema v3 把内部 ID 映射为整数下标，并让正反向索引引用同一配方数组，避免完整对象重复。浏览器加载后使用 Map 与紧凑数组查询，常规正反向查询可以稳定保持在毫秒级。

当前不需要 SQLite。只有未来引入大量用户路线、存档历史或跨数据集复杂统计时，数据库才会提供明显收益。

## 4. 路径规划可行性

最少代数不是枚举所有树，而是对配方矩阵做动态规划，因此可先准确得到每个帕鲁的最短代数。只有结果不超过展示上限时才构造一棵推荐树。

指定 N 代使用精确深度可达性表与受限回溯。管理员默认最多展示 6 代，最高 12；同一路径循环排除和搜索预算共同控制异常组合爆炸。计算位于 Worker，不阻塞 React 主线程。

## 5. Electron 取舍

Electron 体积大于原生 WebView 方案，但当前项目已经具备完整 React/Vite 工程与 Windows 一键打包，使用 Electron 可以降低实施与环境维护成本。减小体积的主要措施：

- 只产出 Windows x64 portable。
- 启用 ASAR 与 maximum compression。
- 图片不重复嵌入多个数据结构。
- Schema v3 只保存一份紧凑配方数组。
- 构建与 Electron 缓存集中在 `build/`，不进入最终业务资源。

未来若安装包体积成为首要目标，可评估 Tauri 2，但需要引入 Rust、Windows WebView2 和新的打包/协议测试矩阵，不作为当前阶段迁移项。

## 6. 环境

- Node.js 22.12+
- npm 10+
- Windows 10/11 x64（EXE 打包）
- 首次安装依赖与刷新来源需要网络；运行应用和缓存重解析不需要网络。

## 7. 风险

| 风险 | 控制 |
| --- | --- |
| paldb 页面结构变化 | fixture、关键字段覆盖率和内容快照校验 |
| robots 或来源策略变化 | 每次同步先检查，禁止即终止 |
| 配方版本漂移 | 固定 tag、commit、文件哈希与游戏 Build ID |
| 路径组合爆炸 | 最短 DP、精确上限、无环约束、搜索预算、Worker |
| 图片损坏 | WebP 文件头与哈希校验、UI 本地占位 |
| 本地配置损坏 | zod/领域解析、默认 6 回退、恢复提示 |
| 素材公开分发权 | 本机缓存不入库，发行前单独确认 |
