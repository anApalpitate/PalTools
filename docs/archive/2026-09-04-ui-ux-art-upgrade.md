# UI/UX 美术升级（已完成）

以下任务记录从 `docs/tasks/todolist.md` 原样归档；当前稳定行为已提升到产品需求、架构说明、路线图与 README。

## UI/UX 美术升级

目标：把应用打磨成成熟、克制、信息清晰的桌面工具，形成“精致的本地资料管理工具 + 轻量游戏世界观”的统一视觉语言，同时保持现有业务行为和操作习惯。

### 待实施内容

- [ ] 审计导航、页面标题、内容层级、留白、信息密度、字体、间距、圆角、边框、阴影与组件复用情况，按影响与风险确定实施顺序。
- [ ] 统一主题语义令牌，覆盖 canvas、surface、surface-raised、text、text-muted、border、accent、warning、danger、focus 等角色；保持各主题独立性，避免业务组件直接判断主题名称或散落主题专属颜色。
- [ ] 优化导航、面板、卡片、弹窗、表单、筛选器、标签页、按钮、数据列表和详情区的层级与状态反馈，但不随意改变用户熟悉的操作位置。
- [ ] 统一图标尺寸、线宽与对齐；优先复用主题化内联 SVG，只有 SVG 无法满足需求时才考虑位图素材。
- [ ] 完善空、加载、错误、禁用、危险、悬停、按压、选中和焦点状态，确保关键状态不只依赖颜色表达。
- [ ] 检查长文本、窄屏和低高度布局，明确页面与内部容器的滚动归属，消除意外横向滚动、文字遮挡和弹窗溢出。
- [ ] 增加只服务于状态理解的克制动效，通常控制在 100–240ms，优先使用 `transform` 和 `opacity`，支持 `prefers-reduced-motion`，不使用 `transition: all` 或持续装饰动画。
- [ ] 仅在现有实现无法支撑设计决策时开展定向联网调研；记录参考来源、可借鉴点、适配方式和不采用的原因，不引入远程字体、在线图标或其他第三方运行时资源。
- [ ] 保持 CSS 和组件边界可维护：优先复用现有令牌与组件，只在明确重复或职责混乱时拆分，不建立超出当前需求的抽象层。

### 验收清单

- [ ] 逐一检查所有现有主题的可辨识性、文字与控件对比度，以及普通、悬停、按压、选中、禁用、危险和焦点状态。
- [ ] 在 1440×900、1152×720、1366×768 及一个窄屏或低高度视口完成真实浏览器回归。
- [ ] 检查 DOM 几何、计算样式、滚动区域、图片加载、控制台错误/警告、第三方请求、键盘导航、焦点恢复、Escape、滚轮与触控板滚动。
- [ ] 确认没有新增横向溢出、文字遮挡、破图、不可点击遮罩、错误焦点或明显布局抖动。
- [ ] 运行相关定点测试、完整测试、类型检查和生产构建；按仓库规范更新文档并提交本次改动。

### 边界

- 不修改数据业务规则、存储协议、Electron 安全边界或离线能力。
- 不实现与视觉升级无关的功能，不进行无关重构或全仓库格式化。
- 不以装饰性牺牲信息扫描效率，不做游戏启动器、营销落地页或通用 SaaS 后台风格。

## 验证结果

- 定向参考来源为 2026-09-04 获取的 [Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md)。可借鉴点是可见焦点、语义表单、明确状态、固有图片尺寸和 reduced-motion；本项目把它们适配为主题级焦点令牌、内联 SVG、弹窗焦点圈定与只使用 transform/opacity 的短状态动效。
- 未采用把全部临时筛选状态写入 URL、为普通列表引入额外虚拟化依赖等通用建议：前者会改变现有本地会话行为，后者不符合这次外科手术式视觉升级的范围；继续使用现有哈希路由、内容可见性优化和本地数据边界，不引入远程字体、在线图标或第三方运行时资源。
- 定点测试 92 项、完整测试 218 项通过；生产构建包含数据校验与 TypeScript 构建并通过。
- Playwright 覆盖 1440×900、1152×720、1366×768、800×640 的图鉴、正向查询、反向查询、方案网和设置页；20 个组合均无横向溢出，视口内图片无破图。
- 七套主题的结构、正文、次级文字、控件边界、强调、警告、危险与焦点令牌均有计算样式和对比度测试；选中、禁用与危险状态同时保留文字或原生语义。
- 图鉴详情在 1152×720 下验证双滚动区、短块进度、Tab 首尾圈定、Escape 关闭、背景滚动锁与触发卡片焦点恢复；方案网验证五个背包按钮保持单行及窄屏抽屉焦点恢复。
