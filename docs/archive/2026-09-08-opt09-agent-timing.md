# OPT-09 原始待办记录

以下为实施前的原始事项，完成行为见 [快捷命令](../reference/07-quick-commands.md)。

### OPT-09：Agent 开发耗时记录与卡点分析

- 现状依据：`output/agent-runs/*.jsonl` 已能按任务和阶段记录 `start`、结束事件及 `durationSec`，但当前耗时是事件之间的墙钟时间。现有样本中存在超过五小时的验证记录、相互重叠的验证与文档阶段、未闭合的 `start`，以及结束事件缺少耗时的情况；中断、侧边对话和等待会被计入实现时间，阶段耗时不能直接相加。
- 记录边界：扩展现有 `agent:log`，明确 `pause`/`resume` 或等价的活跃时间字段；等待用户、工具执行、沙箱审批、受管服务和会话中断需要可区分。中断前闭合或暂停阶段，恢复后继续原阶段，不以事后补写制造虚假耗时。
- 验证拆分：在保留阶段总览的同时，分别记录定点测试、完整测试、Web build、浏览器回归、Electron smoke 和打包等高成本步骤的命令耗时、结果及重试次数；日志仍只写摘要，不写密钥、环境变量值或大段输出。
- 汇总规则：任务总活跃耗时按不重叠时间区间计算，并行阶段取区间并集；墙钟耗时单独展示。报告需列出最长阶段、最长命令、失败重试、等待占比、未闭合记录和数据可信度，避免把暂停时间解释为开发卡点。
- 定点验收：用固定日志样例覆盖正常完成、并行阶段、暂停恢复、跨日、中断后继续、失败重试、缺失结束事件和旧格式兼容。断言活跃耗时不重复累计、墙钟耗时可追溯、未闭合阶段会被明确报告；再用一次真实多阶段任务验证报告能够定位具体命令或等待来源。
